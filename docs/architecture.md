# Архитектура

## Платформа

- React Native с Expo;
- TypeScript в строгом режиме;
- iPhone с Expo Go для ручной проверки UI;
- Expo Web и устанавливаемая PWA для бесплатной пользовательской поставки;
- Windows для разработки и автоматических проверок;
- SQLite через `expo-sqlite` на native;
- IndexedDB за отдельной реализацией репозиториев на web.

Версия Expo SDK выбирается по совместимости с Expo Go на iPhone, фиксируется в
репозитории и обновляется только отдельной задачей.

`expo-sqlite` для web не используется: его web-поддержка требует WASM и
специальных COOP/COEP-заголовков. Web-адаптер хранит полный снимок в IndexedDB и
обеспечивает те же операции и атомарность через readwrite-транзакции браузера.

## Границы компонентов

```text
экраны и компоненты
        ↓
операции приложения
        ↓
правила и типы предметной области
        ↓
интерфейсы репозиториев
        ↓
SQLite (native) / браузерное хранилище (web)
```

React-компоненты не содержат SQL, обращения к IndexedDB или проверки платформы.
Платформенные реализации репозиториев выбираются в точке композиции. Статистика,
клонирование и валидация должны тестироваться без отрисовки экрана.

Обе реализации обеспечивают одинаковое наблюдаемое поведение и атомарность
операций. Если выбранное web-хранилище не позволяет буквально повторить SQL-
транзакцию, адаптер обязан обеспечить эквивалентный результат на уровне операции.

## Модель данных

### Exercise

- `id`, `name`, `muscleGroup`, `isArchived`, `createdAt`, `updatedAt`.

### Workout

- `id`, `date` в формате `YYYY-MM-DD`, `createdAt`, `updatedAt`.

### WorkoutExercise

- `id`, `workoutId`, `exerciseId`, `position`.

### ExerciseSet

- `id`, `workoutExerciseId`, `weight`, `repetitions`, `position`.

Внешние ключи сохраняют целостность данных. Клонирование — атомарная транзакция:
сохраняется либо полный клон, либо ничего.

## PWA и офлайн-режим

- Статический web-бандл размещается по HTTPS; платный backend и собственный домен
  не требуются.
- Web App Manifest позволяет установить приложение на домашний экран iPhone.
- Service worker кэширует только версионированные файлы приложения и обеспечивает
  запуск без сети. Пользовательские данные хранятся отдельно от этого кэша.
- Стратегия обновления не должна оставлять несовместимую смесь старых и новых
  файлов. Обновление активируется целиком и не удаляет пользовательское хранилище.
- Приложение вызывает Storage API для запроса persistent storage, обрабатывает
  отказ и ошибки квоты и не обещает абсолютную сохранность браузерных данных.
- Production URL считается идентификатором хранилища. Перенос на другой origin
  выполняется через экспорт и импорт, а не неявную миграцию.
- Постоянный production URL — `https://psvmchannel.github.io/gymtracker/`.
  Статические ресурсы, manifest и service worker публикуются с базовым путём
  `/gymtracker/`.

## Переносимый формат данных

Экспорт содержит номер версии схемы и полный согласованный снимок пользовательских
данных. Импорт сначала валидирует структуру, типы, ссылки, уникальность и
поддерживаемую версию, затем применяет данные атомарно. Формат и миграции
тестируются независимо от native- и web-репозиториев. Файл не содержит учётных
данных или телеметрии.

Версия 1 хранится в JSON-объекте с полями `version`, `exportedAt`, `exercises`,
`workouts`, `workoutExercises` и `exerciseSets`. Записи используют те же
идентификаторы, даты, временные метки и позиции, что и модель данных, но имена
полей записываются в `camelCase`. Вычисляемое `normalizedName` не экспортируется
и восстанавливается при импорте.

Импорт версии 1 разрешён только в полностью пустое хранилище. До записи
проверяются структура, типы, версия, календарные даты, уникальность, ссылки и
непрерывность позиций. Проверка пустоты и вставка полного снимка выполняются в
одной транзакции; автоматического объединения или замены данных нет.
Для восстановления в уже использовавшемся приложении доступна отдельная
подтверждаемая очистка всех данных; перед ней интерфейс рекомендует экспорт.

## Даты и статистика

Тренировка относится к календарной дате, а не моменту UTC. Дата хранится как
`YYYY-MM-DD` без преобразования, способного сдвинуть её на соседний день.

Статистика вычисляется, а не хранится:

```text
упражнение + дата тренировки -> максимальный вес подхода
упражнение + дата тренировки -> сумма (вес × повторения) всех подходов
```

Архивированные упражнения остаются в статистике при наличии истории. Объём
считается по исходным дробным значениям веса без промежуточного округления.

## Тестирование

- Unit-тесты: валидация, клонирование, даты, порядок и статистика.
- Тесты репозиториев: SQLite, сохранение, транзакции и архивация.
- Контрактные тесты: одинаковое поведение native- и web-репозиториев.
- PWA-тесты: production web-сборка, manifest, service worker, офлайн-запуск,
  обновление без потери данных, ошибки квоты и экспорт/импорт.
- Тесты компонентов: формы и основные пользовательские действия.
- Ручная проверка на iPhone: UI, клавиатура, навигация, график и сохранение.
- Ручная проверка установленной PWA на iPhone: первый запуск онлайн, запуск в
  авиарежиме, запись и повторное открытие, экспорт и восстановление.

Автоматические UI-тесты iOS не входят в начальный harness: macOS runner и iOS
Simulator отсутствуют.
