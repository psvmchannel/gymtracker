# Harness агентской разработки

## Назначение

Harness даёт coding-агенту достаточный контекст и быструю обратную связь для
небольших изменений без опоры на длинную историю диалога.

## Входные данные задачи

- правила из `AGENTS.md`;
- продуктовый контракт из `docs/product.md`;
- относящиеся к задаче архитектурные решения;
- один ограниченный пользовательский результат;
- критерии приёмки и список того, что не входит в задачу.

## Цикл обратной связи

```text
прочитать задачу и репозиторий
→ внести сфокусированное изменение
→ проверить форматирование, lint, типы и тесты
→ изучить diff
→ собрать затронутые целевые платформы
→ вручную проверить UI на iPhone и, для web-задач, установленную PWA офлайн
→ улучшить код или harness по результатам
```

## Основная команда проверки

`npm run verify` — единая команда для человека, агента и CI. Она проверяет
форматирование, lint, TypeScript, тесты и конфигурацию Expo. Облачная сборка
является редкой контрольной точкой, а не частью каждой задачи.

После появления web-цели основная команда также должна включать production
web-сборку или отдельная обязательная команда должна быть явно указана в задаче.
Изменения хранилища прогоняют один контрактный набор тестов для native- и
web-адаптеров. Изменения PWA дополнительно проверяют manifest, service worker и
поведение обновления; dev-сервер не подтверждает офлайн-готовность.

## Шаблон задачи

```md
# Название задачи

## Пользовательский результат

Что пользователь сможет наблюдать после изменения.

## Критерии приёмки

- Конкретное проверяемое поведение.

## Не входит в задачу

- Близкое поведение, которое не нужно добавлять.

## Автоматическая проверка

- Тесты или команды, подтверждающие результат.

## Ручная проверка на iPhone

- Короткая последовательность действий в Expo Go.

## Ручная проверка PWA

- Первый запуск и установка онлайн, затем запуск и изменение данных в авиарежиме.
- Повторное открытие, обновление, экспорт и восстановление без потери данных.
```

## Инварианты PWA-задач

- Хостинг содержит приложение, но не пользовательские тренировки.
- Кэш service worker и хранилище тренировок имеют разные жизненные циклы.
- Офлайн-проверка выполняется на production-сборке после предварительного
  заполнения кэша.
- Результат `navigator.storage.persist()` проверяется; отказ не блокирует работу,
  но риск и резервное копирование остаются видимыми пользователю.
- Данные привязаны к origin. Preview URL нельзя использовать как постоянное место
  пользовательской установки.
- Переход Expo Go → PWA и смена origin проверяются через экспорт/импорт.
- Деплой PWA после обновлений запускает пользователь вручную через GitHub
  Actions. Агент не запускает и не опрашивает workflow без отдельной просьбы.

## План UX-итерации после MVP

Приоритеты определяют порядок реализации. Каждая задача выполняется отдельным
сфокусированным изменением по шаблону выше; объединять весь план в один diff не
следует.

### P0 — исправить удаление тренировки — завершено

**Пользовательский результат:** кнопка «Удалить тренировку» снова удаляет
открытую тренировку после подтверждения.

**Критерии приёмки:**

- отмена подтверждения не меняет данные;
- подтверждение удаляет выбранную тренировку и возвращает интерфейс в корректное
  состояние;
- удаление работает одинаково с пустой тренировкой и с упражнениями и подходами;
- остальные тренировки, упражнения и статистика не повреждаются;
- поведение покрыто тестом наблюдаемого сценария.

**Проверка:** `npm run verify`, целевые тесты тренировки, ручная проверка на
iPhone в Expo Go и в установленной PWA, включая повторное открытие приложения.

### P1 — исправить нижний отступ навигации на iPhone — завершено

**Пользовательский результат:** нижняя навигация не прижимается к краю экрана и
не пересекается с индикатором Home.

**Критерии приёмки:** используется системная safe area, а не отступ под одну
модель iPhone; содержимое и навигация остаются доступны при разной высоте экрана.

**Проверка:** `npm run verify`, `npm run export:web`, ручная проверка портретной
ориентации в Expo Go и установленной PWA на iPhone.

### P1 — сделать строки активных упражнений устойчивыми и компактными — завершено

**Пользовательский результат:** длинное название остаётся внутри карточки, а
действия доступны как аккуратные иконки изменения и удаления.

**Критерии приёмки:**

- название не выталкивает действия за правый край и предсказуемо переносится или
  сокращается;
- иконки имеют понятные accessibility labels и достаточную область нажатия;
- подтверждение и семантика изменения и удаления не меняются;
- решение не требует новой production-зависимости без отдельного обоснования.

**Проверка:** `npm run verify`, ручная проверка короткого и заведомо длинного
русского названия на iPhone в Expo Go и PWA.

**Замечания ручной проверки для следующей итерации:**

- иконки редактирования и удаления визуально находятся далеко друг от друга;
- крестик удаления стоит сместить вправо на несколько пикселей;
- карандаш нужно заменить на более простую и изящную иконку и сместить вправо
  примерно на 4–6 пикселей.

### P1 — сгруппировать активные упражнения — завершено

**Пользовательский результат:** список «Активные упражнения» разбит на секции по
мышечным группам.

**Критерии приёмки:** каждое упражнение отображается ровно в одной секции;
порядок секций и упражнений детерминирован; пустые секции не создают визуальный
шум; редактирование и удаление продолжают работать внутри секций.

**Проверка:** тест группировки как отдельного преобразования данных,
`npm run verify`, ручная проверка списка с несколькими группами на iPhone.

### P1 — улучшить подсказку названия упражнения — завершено

**Пользовательский результат:** пустое поле нового упражнения показывает серый
placeholder «Например, жим лёжа»; введённый текст сохраняет обычный цвет.

**Проверка:** `npm run verify` и ручная проверка пустого, активного и заполненного
поля на iPhone.

### P1 — уточнить действия тренировки — завершено

**Пользовательский результат:** текстовая кнопка «Удалить» у подхода заменена
красным крестиком в стиле раздела «Упражнения». Кнопки «Добавить» не меняются.

**Критерии приёмки:** крестик имеет понятную accessibility label и достаточную
область нажатия; подтверждение и семантика удаления подхода не меняются; другие
действия раздела «Тренировки» остаются без изменений.

**Проверка:** `npm run verify`, ручная проверка удаления подхода и неизменившихся
кнопок «Добавить» на iPhone в Expo Go и PWA.

### P0 — исправить удаление подхода и проверить остальные удаления — завершено

**Пользовательский результат:** кнопка «Удалить» у подхода удаляет выбранный
подход после подтверждения. Все остальные действия удаления в приложении также
нужно проверить и исправить, если они не выполняются по той же причине.

**Критерии приёмки:** отмена подтверждения не меняет данные; подтверждение
удаляет только выбранную сущность; проверены удаление подхода, упражнения из
каталога, тренировки и полная очистка данных.

**Результат аудита:** существующие удаления подхода, упражнения из каталога,
тренировки и всех данных используют общий платформенный механизм подтверждения.
Удаление упражнения из тренировки ещё не реализовано и остаётся отдельной задачей
P1 ниже.

### P1 — показывать группу при добавлении упражнения в тренировку — завершено

**Пользовательский результат:** в списке выбора упражнения рядом с его названием
указана мышечная группа.

**Проверка:** `npm run verify`, ручная проверка списка с упражнениями из
нескольких групп на iPhone в Expo Go и PWA.

### P1 — менять порядок упражнений в тренировке перетаскиванием — завершено

**Пользовательский результат:** упражнения в тренировке можно менять местами с
помощью drag-and-drop; новый порядок сохраняется после перезапуска приложения.

**Критерии приёмки:** перетаскивание начинается за отдельный маркер и не меняет
подходы упражнения; сохраняется полная перестановка без дубликатов и пропусков;
порядок одинаково сохраняется в native- и web-хранилище.

**Проверка:** контрактные тесты обоих хранилищ, `npm run verify`, ручная проверка
перетаскивания трёх упражнений, повторного открытия тренировки и перезапуска на
iPhone в Expo Go и PWA.

### P1 — сворачивать подходы и перетаскивать упражнение одним контролом — проверено в Expo Go, ожидает PWA

**Пользовательский результат:** короткое нажатие на стрелку сворачивает или
раскрывает подходы упражнения. При удержании карточки стрелка превращается в
маркер перетаскивания, после чего упражнение можно переместить вверх или вниз.

**Критерии приёмки:** состояние карточек независимо; сворачивание не меняет
подходы и черновики полей; кнопка имеет доступное имя и сообщает раскрытое
состояние; обычное короткое нажатие не запускает перетаскивание; удержание даёт
понятную визуальную обратную связь и не сворачивает карточку; после завершения
или отмены жеста возвращается стрелка; новый порядок сохраняется после
перезапуска в native- и web-хранилище.

**Проверка:** `npm run verify`, ручная проверка независимого сворачивания,
сохранности введённого черновика, перехода контрола в режим перетаскивания и
перемещения свёрнутых и раскрытых карточек разной высоты на iPhone в Expo Go и
PWA.

### P1 — приглушить подсказки полей подхода — проверено в Expo Go, ожидает PWA

**Пользовательский результат:** placeholder-текст «Вес, кг» и «Повторы» в
разделе «Тренировки» отображается более приглушённым цветом по образцу поля
названия при добавлении упражнения.

**Проверка:** `npm run verify`, ручное сравнение цвета подсказок полей подхода с
подсказкой названия упражнения на iPhone в Expo Go и установленной PWA.

### P1 — переводить фокус в форму выбранного подхода — проверено в Expo Go, ожидает PWA

**Пользовательский результат:** при нажатии на существующий подход в упражнении
раздела «Тренировки» открывается его редактирование, а фокус сразу переходит в
первое поле формы подхода («Вес, кг») с открытием клавиатуры.

**Критерии приёмки:** значения выбранного подхода подставляются до установки
фокуса; нажатие на другой подход переводит редактирование и фокус на него;
удаление подхода и прокрутка списка продолжают работать независимо.

**Проверка:** `npm run verify`, ручная проверка выбора первого, другого и уже
редактируемого подхода на iPhone в Expo Go и установленной PWA: значения должны
появиться до фокуса, поле веса получить курсор, а клавиатура — открыться.

### P1 — выделять редактируемый подход или упражнение — проверено в Expo Go, ожидает PWA

**Пользовательский результат:** подход в тренировке и упражнение в каталоге,
которые сейчас редактируются, визуально отличаются от остальных элементов
списка до сохранения или отмены редактирования.

**Критерии приёмки:** выделяется только текущий элемент; выделение не заменяет
доступное текстовое состояние формы; после сохранения, отмены или перехода к
редактированию другого элемента прежнее выделение исчезает.

**Проверка:** `npm run verify`, ручная проверка переключения выделения между
подходами и упражнениями, а также его снятия после сохранения или отмены на
iPhone в Expo Go и установленной PWA.

### P1 — приглушить порядковые номера подходов — проверено в Expo Go, ожидает PWA

**Пользовательский результат:** порядковый номер подхода отображается серым
цветом и визуально не конкурирует со значениями веса и повторений.

**Критерии приёмки:** номер отображается без точки в отдельной фиксированной
колонке; значения подходов начинаются на одной вертикали и сохраняют текущую
контрастность, а строка остаётся читаемой в Expo Go и установленной PWA.

**Проверка:** `npm run verify`, ручная проверка строк с однозначными и
двузначными номерами подходов на iPhone в Expo Go и установленной PWA.

### P1 — автоматически открывать сегодняшнюю тренировку — проверено в Expo Go, ожидает PWA

**Пользовательский результат:** при открытии раздела «Тренировки» автоматически
открывается последняя тренировка, если её дата совпадает с текущей датой.

**Критерии приёмки:** текущая дата передаётся в логику явно; сравнение выполняется
по локальной календарной дате; если последняя тренировка создана не сегодня или
тренировок нет, сохраняется текущее стартовое состояние раздела; новая
тренировка не создаётся автоматически.

**Проверка:** `npm run verify`, целевые тесты выбора по локальной дате, ручная
проверка запуска раздела с тренировкой за сегодня, только с прошлыми
тренировками и без тренировок на iPhone в Expo Go и установленной PWA.

**Проверка пяти улучшений:** `npm run verify`, целевые тесты выбора сегодняшней
тренировки и состояний редактирования, ручная проверка фокуса, клавиатуры,
выделения, контрастности и жестов на iPhone в Expo Go и установленной PWA.

### P1 — удалять упражнение из тренировки — проверено в Expo Go, ожидает PWA

**Пользовательский результат:** добавленное упражнение можно удалить из текущей
тренировки после подтверждения, не удаляя его из каталога и других тренировок.

**Критерии приёмки:** вместе со связью удаляются её подходы; позиции оставшихся
упражнений становятся непрерывными; каталог упражнений и другие тренировки не
изменяются; отмена подтверждения ничего не удаляет.

**Проверка:** `npm run verify`, контрактные тесты native- и web-хранилища,
ручная проверка отмены и подтверждения удаления на iPhone в Expo Go и
установленной PWA.

### P2 — добавить переключатель метрики статистики — проверено в Expo Go, ожидает PWA

**Пользовательский результат:** для выбранного упражнения пользователь
переключает график между максимальным весом и объёмом нагрузки тренировки.

**Правило расчёта:** объём упражнения за тренировку равен сумме
`вес × повторения` по всем его подходам. Например, четыре подхода по 10
повторений с весом 50 кг дают 2000 кг.

**Критерии приёмки:**

- переключатель явно показывает выбранную метрику;
- график, подписи, пустое состояние и состояние одной точки соответствуют
  выбранной метрике;
- дробный вес рассчитывается без преждевременного округления;
- максимальный вес продолжает рассчитываться по прежним правилам;
- расчёт объёма отделён от React-компонента и покрыт детерминированными тестами.

**Проверка:** unit-тесты обеих метрик, `npm run verify`, `npm run export:web`,
ручная сверка известного примера на iPhone в Expo Go и установленной PWA.

### Общий порядок выполнения

1. Воспроизвести и исправить удаление тренировки (P0).
2. Исправить safe area и переполнение строки упражнения (P1).
3. Добавить группировку, иконки и placeholder упражнений (P1).
4. После уточнения оформить действия тренировки отдельной задачей (P1).
5. Реализовать переключаемую статистику объёма (P2).
6. После каждой UI-задачи записать результат ручной проверки на iPhone в журнал
   обучения и `docs/checkpoint.md`.

## Журнал обучения

После этапа отмечай: какого контекста не хватило агенту, что поймали тесты, что
нашлось только на iPhone, привели ли инструкции к лишней работе и нужно ли новое
постоянное правило. Не добавляй постоянную инструкцию из-за единичной ошибки.

### Этап 0 — каркас проекта

- Автоматические проверки поймали несовместимые с Expo SDK 57 версии Jest;
  зависимости были выровнены по рекомендации Expo Doctor.
- На физическом iPhone обнаружено требование авторизации: Expo Go и Expo CLI
  должны использовать одну учётную запись.
- Вход через Google выполняется командой `npx expo login --browser`. Флаг
  `--sso` предназначен для организационного SSO и в этом сценарии не подходит.
- В текущем окружении Windows автоматическое открытие браузера завершалось
  ошибкой `cmd.exe /c start`. Рабочий обход описан в README через
  `$env:BROWSER = 'none'` и ручное открытие одноразовой ссылки.
- CLI успешно авторизован как `psvmchannel`. Повторный запуск приложения на
  iPhone после авторизации ещё не проверен пользователем.
- Новое постоянное правило в `AGENTS.md` не требуется: проблема относится к
  локальному запуску и документирована в README.

### Этап 8 — UX-итерация после MVP

- 18 сентября 2026 года пользователь проверил в Expo Go объединённое управление
  сворачиванием и перетаскиванием, оформление и фокус редактирования подходов,
  автоматическое открытие сегодняшней тренировки, удаление упражнения из
  тренировки и переключение статистики между максимальным весом и объёмом
  нагрузки. В ходе проверки уточнены шеврон, маркер редактирования, колонка
  номера подхода и стабильная высота блока статистики; повторное нажатие на уже
  выбранное упражнение больше не оставляет экран в состоянии загрузки.
- Те же изменения ещё требуют ручной проверки в установленной PWA.

- Пользователь подтвердил на iPhone в установленной PWA серый placeholder
  «Например, жим лёжа» в пустом поле названия упражнения.
- После деплоя первое открытие PWA установило обновление service worker, а новая
  сборка отобразилась после второго полного закрытия и запуска приложения.
- Новое постоянное правило не требуется: это ожидаемое поведение текущей
  стратегии обновления PWA, а пользовательские данные очищать не пришлось.

### Этап 9 — доводка PWA и графика статистики

- В PWA перетаскивание упражнений больше не запускает выделение текста.
- В каталоге упражнений используется единая геометрия кнопок редактирования и
  удаления; крестик удаления вынесен в общий компонент и применяется также к
  подходам тренировки. Фон состояния нажатия у иконок удалён.
- Стандартная синяя web-обводка полей ввода отключена, при этом native-стили не
  изменены. После добавления подхода фокус возвращается в поле веса для быстрого
  ввода следующего подхода.
- График статистики получил оси и подписанные деления. Раскладка поддерживает
  отдельные отступы с каждой стороны, чтобы использовать ширину карточки и не
  обрезать подписи.
- Автоматические проверки и production web-сборка проходят. Изменения требуют
  итоговой ручной проверки в установленной PWA на iPhone; отдельно следует
  оценить задержку первого отображения растровой иконки редактирования.
