# Harness агентской разработки

## Назначение

Harness даёт coding-агенту достаточный контекст и быструю обратную связь для
небольших изменений без опоры на длинную историю диалога.

## Входные данные задачи

- правила из `AGENTS.md`;
- продуктовый контракт из `docs/product.md`;
- относящиеся к задаче архитектурные решения;
- один ограниченный пользовательский результат;
- критерии приёмки и список того, что не входит в задачу.

## Цикл обратной связи

```text
прочитать задачу и репозиторий
→ внести сфокусированное изменение
→ проверить форматирование, lint, типы и тесты
→ изучить diff
→ собрать затронутые целевые платформы
→ вручную проверить UI на iPhone и, для web-задач, установленную PWA офлайн
→ улучшить код или harness по результатам
```

## Основная команда проверки

`npm run verify` — единая команда для человека, агента и CI. Она проверяет
форматирование, lint, TypeScript, тесты и конфигурацию Expo. Облачная сборка
является редкой контрольной точкой, а не частью каждой задачи.

После появления web-цели основная команда также должна включать production
web-сборку или отдельная обязательная команда должна быть явно указана в задаче.
Изменения хранилища прогоняют один контрактный набор тестов для native- и
web-адаптеров. Изменения PWA дополнительно проверяют manifest, service worker и
поведение обновления; dev-сервер не подтверждает офлайн-готовность.

## Шаблон задачи

```md
# Название задачи

## Пользовательский результат

Что пользователь сможет наблюдать после изменения.

## Критерии приёмки

- Конкретное проверяемое поведение.

## Не входит в задачу

- Близкое поведение, которое не нужно добавлять.

## Автоматическая проверка

- Тесты или команды, подтверждающие результат.

## Ручная проверка на iPhone

- Короткая последовательность действий в Expo Go.

## Ручная проверка PWA

- Первый запуск и установка онлайн, затем запуск и изменение данных в авиарежиме.
- Повторное открытие, обновление, экспорт и восстановление без потери данных.
```

## Инварианты PWA-задач

- Хостинг содержит приложение, но не пользовательские тренировки.
- Кэш service worker и хранилище тренировок имеют разные жизненные циклы.
- Офлайн-проверка выполняется на production-сборке после предварительного
  заполнения кэша.
- Результат `navigator.storage.persist()` проверяется; отказ не блокирует работу,
  но риск и резервное копирование остаются видимыми пользователю.
- Данные привязаны к origin. Preview URL нельзя использовать как постоянное место
  пользовательской установки.
- Переход Expo Go → PWA и смена origin проверяются через экспорт/импорт.

## План UX-итерации после MVP

Приоритеты определяют порядок реализации. Каждая задача выполняется отдельным
сфокусированным изменением по шаблону выше; объединять весь план в один diff не
следует.

### P0 — исправить удаление тренировки — реализовано, ожидает ручной проверки

**Пользовательский результат:** кнопка «Удалить тренировку» снова удаляет
открытую тренировку после подтверждения.

**Критерии приёмки:**

- отмена подтверждения не меняет данные;
- подтверждение удаляет выбранную тренировку и возвращает интерфейс в корректное
  состояние;
- удаление работает одинаково с пустой тренировкой и с упражнениями и подходами;
- остальные тренировки, упражнения и статистика не повреждаются;
- поведение покрыто тестом наблюдаемого сценария.

**Проверка:** `npm run verify`, целевые тесты тренировки, ручная проверка на
iPhone в Expo Go и в установленной PWA, включая повторное открытие приложения.

### P1 — исправить нижний отступ навигации на iPhone

**Пользовательский результат:** нижняя навигация не прижимается к краю экрана и
не пересекается с индикатором Home.

**Критерии приёмки:** используется системная safe area, а не отступ под одну
модель iPhone; содержимое и навигация остаются доступны при разной высоте экрана.

**Проверка:** `npm run verify`, `npm run export:web`, ручная проверка портретной
ориентации в Expo Go и установленной PWA на iPhone.

### P1 — сделать строки активных упражнений устойчивыми и компактными

**Пользовательский результат:** длинное название остаётся внутри карточки, а
действия доступны как аккуратные иконки изменения и удаления.

**Критерии приёмки:**

- название не выталкивает действия за правый край и предсказуемо переносится или
  сокращается;
- иконки имеют понятные accessibility labels и достаточную область нажатия;
- подтверждение и семантика изменения и удаления не меняются;
- решение не требует новой production-зависимости без отдельного обоснования.

**Проверка:** `npm run verify`, ручная проверка короткого и заведомо длинного
русского названия на iPhone в Expo Go и PWA.

### P1 — сгруппировать активные упражнения

**Пользовательский результат:** список «Активные упражнения» разбит на секции по
мышечным группам.

**Критерии приёмки:** каждое упражнение отображается ровно в одной секции;
порядок секций и упражнений детерминирован; пустые секции не создают визуальный
шум; редактирование и удаление продолжают работать внутри секций.

**Проверка:** тест группировки как отдельного преобразования данных,
`npm run verify`, ручная проверка списка с несколькими группами на iPhone.

### P1 — улучшить подсказку названия упражнения

**Пользовательский результат:** пустое поле нового упражнения показывает серый
placeholder «Например, жим лёжа»; введённый текст сохраняет обычный цвет.

**Проверка:** `npm run verify` и ручная проверка пустого, активного и заполненного
поля на iPhone.

### P1 — уточнить действия тренировки

Запрос зафиксирован в исходной формулировке: «Кнопки “Добавить”, “Удалить”» в
разделе «Тренировки». Перед изменением нужно уточнить желаемый результат:
заменить текст иконками, изменить расположение, подписи или другое поведение.
До уточнения эта задача не должна менять интерфейс.

### P2 — добавить переключатель метрики статистики

**Пользовательский результат:** для выбранного упражнения пользователь
переключает график между максимальным весом и общим объёмом тренировки.

**Правило расчёта:** объём упражнения за тренировку равен сумме
`вес × повторения` по всем его подходам. Например, четыре подхода по 10
повторений с весом 50 кг дают 2000 кг.

**Критерии приёмки:**

- переключатель явно показывает выбранную метрику;
- график, подписи, пустое состояние и состояние одной точки соответствуют
  выбранной метрике;
- дробный вес рассчитывается без преждевременного округления;
- максимальный вес продолжает рассчитываться по прежним правилам;
- расчёт объёма отделён от React-компонента и покрыт детерминированными тестами.

**Проверка:** unit-тесты обеих метрик, `npm run verify`, `npm run export:web`,
ручная сверка известного примера на iPhone в Expo Go и установленной PWA.

### Общий порядок выполнения

1. Воспроизвести и исправить удаление тренировки (P0).
2. Исправить safe area и переполнение строки упражнения (P1).
3. Добавить группировку, иконки и placeholder упражнений (P1).
4. После уточнения оформить действия тренировки отдельной задачей (P1).
5. Реализовать переключаемую статистику объёма (P2).
6. После каждой UI-задачи записать результат ручной проверки на iPhone в журнал
   обучения и `docs/checkpoint.md`.

## Журнал обучения

После этапа отмечай: какого контекста не хватило агенту, что поймали тесты, что
нашлось только на iPhone, привели ли инструкции к лишней работе и нужно ли новое
постоянное правило. Не добавляй постоянную инструкцию из-за единичной ошибки.

### Этап 0 — каркас проекта

- Автоматические проверки поймали несовместимые с Expo SDK 57 версии Jest;
  зависимости были выровнены по рекомендации Expo Doctor.
- На физическом iPhone обнаружено требование авторизации: Expo Go и Expo CLI
  должны использовать одну учётную запись.
- Вход через Google выполняется командой `npx expo login --browser`. Флаг
  `--sso` предназначен для организационного SSO и в этом сценарии не подходит.
- В текущем окружении Windows автоматическое открытие браузера завершалось
  ошибкой `cmd.exe /c start`. Рабочий обход описан в README через
  `$env:BROWSER = 'none'` и ручное открытие одноразовой ссылки.
- CLI успешно авторизован как `psvmchannel`. Повторный запуск приложения на
  iPhone после авторизации ещё не проверен пользователем.
- Новое постоянное правило в `AGENTS.md` не требуется: проблема относится к
  локальному запуску и документирована в README.
