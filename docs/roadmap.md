# План реализации MVP

Каждый этап — вертикальный срез (vertical slice), после которого репозиторий
остаётся рабочим.

## 0. Каркас проекта и проверка — реализован

Результат: минимальное приложение открывается на iPhone через Expo Go, а агент
проверяет репозиторий одной командой.

- Создать совместимый Expo-проект с TypeScript.
- Настроить строгий TypeScript, lint, форматирование и тесты.
- Добавить `npm run verify`.
- Добавить разделы Тренировки, Упражнения и Статистика.
- Описать запуск на Windows и iPhone.

## 1. Каталог упражнений — реализован

Результат: пользователь создаёт, просматривает и изменяет упражнения с мышечной
группой. Данные сохраняются в SQLite, ошибки валидации понятны, правила покрыты
unit-тестами и тестами репозитория.

## 2. Запись тренировки — реализован

Результат: пользователь создаёт тренировку на дату, добавляет упражнения и
добавляет, изменяет и удаляет подходы. Порядок и изменения сохраняются.

## 3. История, клонирование и удаление упражнений — реализован, ожидает ручной проверки

Результат: тренировки отображаются по датам, старая тренировка атомарно
клонируется, неиспользованные упражнения удаляются, а использованные архивируются
без повреждения истории.

## 4. График прогресса — реализован

Результат: пользователь выбирает упражнение и видит максимальный вес по датам.
Поддерживаются состояния без данных, с одной и несколькими точками.

## 5. Стабилизация MVP — реализован

Результат: основной сценарий надёжно работает на iPhone через Expo Go. Выполнена
ручная проверка, исправлены существенные дефекты, проверено сохранение после
перезапуска и описаны ограничения.

## 6. Перенос данных — реализован

Результат: пользователь экспортирует полный согласованный снимок данных из
версии Expo Go и импортирует его без скрытого объединения или перезаписи. Формат
JSON имеет версию, валидируется и покрыт тестами миграции и повреждённых файлов.

## 7. Бесплатная офлайн-PWA — локальная реализация готова

Результат: приложение размещено на бесплатном статическом HTTPS-хостинге,
устанавливается на домашний экран iPhone и выполняет основной сценарий в
авиарежиме без ноутбука и Metro.

- Подключить и регулярно проверять Expo Web.
- Реализовать web-репозитории с тем же контрактом, что у SQLite-репозиториев.
- Добавить manifest, иконки и осторожную стратегию service worker.
- Запрашивать persistent storage и явно обрабатывать отказ и исчерпание квоты.
- Проверить обновление PWA без потери локальных данных.
- Импортировать экспорт из этапа 6 и предоставить обратный экспорт.
- Зафиксировать постоянный production origin; смену адреса проводить только с
  документированным переносом данных.

Постоянный origin выбран: `https://psvmchannel.github.io/gymtracker/`.
Автоматическая публикация выполняется из ветки `main` через GitHub Actions.
